# M3 持久任务与故障恢复验收

日期：2026-10-07。M3-01～M3-06 在本地 PostgreSQL 18.6 完成有限故障矩阵验收，继续 M4。新增真实模型调用 0，累计保守费用仍为 1.204930 元，10 元总授权剩余 8.795070 元。

## 执行与提交

全局队列锁控制领取和容量；领取产生 attempt、租约令牌和不可续延的 180 秒 attempt 截止时间。续租、完成和失败处理都检查同一个资格条件。过期扫描有行锁及跳过已锁记录，每个任务最多三次尝试，退避为 1、2 秒，配置最高截断 30 秒。永久拒绝、格式/领域失败不自动恢复为成功。

恢复优先读取已持久化且重新通过当前契约和领域检查的模型响应，记录 `stored_response_replay`，不发新网络请求。模型可能已执行但响应未保存时保留 `outcome_unknown` 和费用预留；恢复可能再次收费，正式发布仍仅接受当前 attempt。

正文、任务成功、完成事件和每个资源请求的事务 outbox 同时提交。中断前全部回滚，成功后重复完成被拒绝。outbox 的 `pending` 是已登记待制作任务，M4 消费；不表示已有图片或文件。单次讲解至多六个资源请求，分别绑定不可变正文版本。

费用预留在账户锁内再次锁定并核验任务，取消或过期不会因等待预算锁后继续获得新预留。已经发出的外部请求仍可能收费；取消限制正式结果提交，不能撤回供应商已执行的推理。

取消/完成竞争暴露过真实 PostgreSQL 死锁。修复为不改变键值的行使用 `FOR NO KEY UPDATE`，正式提交按全局队列锁、空间、任务顺序取得锁，并在锁定后刷新 ORM 对象。该行锁与外键验证的键共享锁兼容，依据 [PostgreSQL 18 行锁文档](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS)。修复后 20 次竞争全部保持单一有效终态。

## 事件与验证

事件递增序号，默认保留七天，只清除连续过期前缀。过期游标返回 410，超前游标返回 409；客户端读取任务快照、继续连接，不重发生成 POST。关闭观察连接不取消任务。HTTP SSE 用同次批量读取的快照判断终态，避免终态与事件读取的竞争漏报。

**155 项 Python 测试通过，0 跳过；Chromium 5/5；统一入口 10 项检查通过。** 类型、格式、33 份 schema、前端构建、M0/M1/M2 历史证据回放通过。远程 CI 仍未运行。

| 故障点 | 次数与观察结果 |
| --- | --- |
| 领取后、模型前 SIGKILL | 1；租约过期扫描后第二次尝试成功，一份正式问答 |
| 响应已保存后 SIGKILL | 1；重验并复用响应，无第二次模型执行 |
| 完成写入后、提交前 SIGKILL | 1；PostgreSQL 回滚正式记录，恢复后只提交一份 |
| 提交后 SIGKILL | 1；终态、内容和事件可读，不再领取 |
| 旧 attempt 在新 attempt 成功后迟到 | 1；旧完成与续租拒绝，新内容不变 |
| 两个恢复扫描者竞争 | 1 组两执行者；仅一个扫描转入等待重试 |
| 取消/完成竞争 | 20；由数据库提交顺序决定 cancelled 或 succeeded，内容数量与终态相符 |
| 排队前后依赖变更 | 排队变更不调用模型，执行中变更转冲突，旧内容不被覆盖 |
| 响应未知、截止时间、退避和三次上限 | 分别检查；保留未知费用，截止不能续延，取消不复活 |
| 资源 outbox 提交中断 | 1；正文、资源登记、终态及事件一起回滚；重试仅登记一个请求 |
| 等待费用锁时取消 | 1；预留和调用记录均为零 |
| 事件过期与浏览器恢复 | 数据库真实前缀清理和 HTTP 410；浏览器注入传输 410 后读取真实快照，生成 POST 仅一次 |

进程故障使用真实子进程 SIGKILL；其它竞争使用独立 PostgreSQL 事务与线程。浏览器的 410 是明确的网络边界注入，不称作真实网络故障。测试仅覆盖所列窗口和样本，不承诺任意故障或外部调用 exactly-once。

## 固定合成负载

预先工作量：64 个独立空间、8 个 HTTP 请求线程、队列容量 32、两个 worker 实例、全局执行资格 2；开发替身固定等待 50 毫秒，不访问模型。先压满队列，再取消八个并开始 worker。

实际接收 32、容量拒绝 32、取消 8、成功 24、失败 0；32 个活动重复别名及 32 个终态原键重发均复用原任务；实际替身执行 24 次，观测峰值 2。POST 任务延迟 P50 22.904 ms / P95 30.224 ms，416 次快照读取 P50 1.376 ms / P95 2.687 ms。处理阶段 0.920 秒、总计 1.456 秒。

这是一次 macOS 单机合成负载，不是生产吞吐或模型并发能力。此前 M2 的 23 次真实供应商调用延迟 P50 3.4147 秒 / P95 10.6666 秒、范围 1.6438～16.6083 秒；本阶段只读取原始记录，未新增推理。这两种延迟分别报告，没有用替身等待推算真实性能。
