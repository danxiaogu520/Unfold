## 实验配置

供应商：DeepSeek；认证 `/models` 返回 `deepseek-flash` 的显示名 `DeepSeek-V4.1-Flash`。供应商别名不能锁定权重快照。环境：本机 macOS arm64、CPython 3.12.14；非思考模式 `reasoning.effort=none`、temperature=0.2、Responses `text.format.type=json_schema`，完整 schema 同时进入提示。本地执行长度、引用、来源与叶子不变量检查；最多一次修复，禁止无界或隐式网络重试。

核心两个开发场景均为每轮 3 次独立试验；补充的 `backend-2`、`triads-1`、`cell-1` 各 1 次，在调用前固定选择。未运行保留集，未以保留集结果修改提示。原始 JSONL 包含可见输出与请求，不保存内部推理。每批记录模型、提示版本、输入选择、源代码 SHA-256 与源码快照，未初始化 Git，因此 `git_revision=null`；指纹不能误写为提交 SHA。

## 失败、修正与兼容性结论

- v1 问卷重复 scope/constraints，或重新细问已有 background/goal；六次候选被拒绝。v2/v3 提示明确每个维度最多一题，动态附上可问维度，不为满足题量强问。
- 目标能力/次要用途被输出成对象而非数组、一次非法 JSON，以及重评多出字段，均被本地检查拒绝。完整 schema 进入提示，有限修复保留失败调用和费用。
- v1 的窄主题三次都被过度拆分；v2 仍有一次。v3 明确单段讲解可承载的单情境无需结构细分，最终三次均为根叶子；没有为了层数硬拆。
- v2 探索器仅走首个分支，浅分支叶子被误记为整个主题过早停止。v3 在固定最多四次展开预算内回溯其他分支，已用替身回归验证；各条实际展开路径保留。执行预算退出不会伪造叶子。
- 补充音乐问卷一次给出 8 个选项，超过本地 6 个上限；一次修复后成功。局部数量与语义仍须应用校验。
- 两组兼容性探针中，正向 schema 通过；冲突提示仍得到 `answer=fail`，与 schema 的 `enum=[pass]` 矛盾。**本环境只证明参数被接受，不能声称 Responses 强制 schema。** 保留本地校验与有限修复作为正式方案，未静默改为自由文本解析。
- 两次故意单 token 输出均归类为 `truncated`，没有变成成功或 leaf。拒答、超时、schema_unsupported、未知外部结果等通过可控响应测试；本轮未实际诱发拒答/超时，不声称真实覆盖了这些供应商行为。

按官方高峰价且全部输入未命中缓存的保守估算为 **0.880300 元**，低于用户授权 **5 元**。前后账户余额观察下降 **0.28 元**；这是账户层观测，无法排除其他客户端同期用量，未取得逐调用账单，因此逐调用实际费用与精确每成功任务费用仍为未知，不能把余额差包装成逐调用核算。剩余保守预算 4.119700 元已写入本地配置，未恢复为新一轮 5 元。

最终核心六条完整学习任务 P50/P95 为 6.120/33.043 秒；补充三条任务为 25.512/38.190 秒（最近秩，小样本）。各阶段耗时也逐次记录。批次 summary 中的 P50/P95 包含链路与阶段探针，不能拿混合数字作为“完整学习链路延迟”。所有数据仅为这次串行小样本，无用户负载、队列等待或数据库提交，不用作线上 SLA/吞吐承诺。

## 接受口径、风险与后续估计

M0 接受标准为全部确定性不变量通过、最终六次核心学习链路与八个阶段探针通过、补充开发样例通过或明确修复、全历史失败保留且费用在上限内。当前标准已满足。后续语义评分规则与初始阈值在 `evaluation.v1` 冻结：0/1/2，适用维度至少 1、均值至少 1.6、用途与停止维度须为 2，不允许已确认的关键错误；独立人工校准尚未执行，保留集必须按同一冻结口径评估。

残余限制：供应商不强制 schema、模型别名与服务端版本可变化、生成事实未独立核验、仅五个开发场景接受过真实实验、保留集与资源实际构建未运行、生物概览分支可能偏早停止。M0 不证明学习效果、练习总体质量、稳定叶子准确率或任务恢复能力。

M1 原估计 3～4 人日调整为 **3～5 人日**，为供应商弱 schema 约束、完整本地校验及恢复记录整合留出余量；其余阶段仍保留原估计，合计初估调整为 **31～47 人日**，并保留 20%～30% 缓冲。本轮未逐段计人工工时，不能把这次 agent 执行墙钟时间换算成人工开发人日。当前 Docker/psql 未在 PATH 中，M1 需要验证真实 PostgreSQL 启动方式。
