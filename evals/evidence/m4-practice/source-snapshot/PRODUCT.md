# 知脉：产品定义

状态：已获授权开始实施，M0 产品参数、生成契约与真实基线已完成验收。更新日期：2026-10-07。技术协议与实现约束见 [DESIGN.md](DESIGN.md)，初始参数与取舍见 [M0 决策](docs/decisions/0001-m0-baseline.md)。应用主流程在 M1/M2 实现。

## 已确认

- 中文名：知脉。英文名和项目目录名：Unfold。
- 产品接受开放领域，不将后端开发或其他单一领域设为使用限制。
- 骨架与内容都由 LLM 提供。先以用途问答确定学习边界，再生成领域大纲并逐层展开。
- LLM 负责判断知识范围、解释程度与是否停止；程序通过结构化协议、状态和执行限制落实决定。
- 每次展开请求聚焦下一层；每个节点必须附带概述。用户阅读节点后主动展开。
- 当前学习设定下被判定为叶子的节点不允许继续展开，仍可阅读讲解、查看例子和做练习。
- 每个知识节点提供练习入口，底层首先支持选择题。
- 正文采用 Markdown 与 LaTeX 公式，图片、图示、可运行代码和动画作为有类型的内容资源展示。
- 不以用户上传 PDF、教材或其他资料作为开始使用的前提，也不把资料转知识树作为核心形态。
- 用户期望持续深入、逐步建立完整的知识体系。产品按当前用途和范围判断内容是否充分，不声称穷尽一个领域。
- 首先自己实际使用，保留之后向他人开放的空间。
- 作为 Agent / AI 应用后端面试的简历项目，积累可演示、可复现的工程成果；技术建设主线见 DESIGN.md，实施顺序见 [PLAN.md](PLAN.md)。这不改变产品接受开放学习领域的范围。
- 已进入 M0 实施；先验收契约与真实生成基线，再建设应用。

## 核心流程

1. 用户输入想学习的领域，也可以直接写出用途和基础。
2. LLM 提出少量用途导向的问题，以选择题为主；已明确的信息不重复询问。
3. 程序保存答案，整理成可见、可修改的学习设定，并用于后续所有生成请求。
4. 问答完成后自动生成根节点概述与第一层大纲，各分支同时带有概述；范围已足够小的主题也可直接将根节点判为叶子。不自动递归生成整棵树。
5. 用户选择节点，阅读概述、讲解、例子及相关联系，理解其位置与范围。
6. 节点允许展开时提供按钮，每次只生成下一层；叶子节点不提供继续展开。
7. 用户可以做与当前已讲内容相匹配的练习，作答后查看解析。
8. 用户可以反馈太浅、太难、遗漏、错误或停止位置不合适，系统据此建议补充讲解、前置知识或重新评估。
9. 正式提交的内容与资源持久保存，再次打开默认复用；重新生成是独立动作。

新增子项可以按规则自动提交；修改旧结构时需要解释变化。学习界面暂建议采用大纲导航、当前内容和局部关系视图，全图为可选视图；首屏布局尚未定稿。

## 用途问答与学习设定

问题应当能改变内容组织，避免让用户直接选择没有参照的“深度等级”。初始参数为累计最多 5 个问题、最多 2 轮，每种用途维度每轮最多一题；已明确的信息不重复询问，足够开始时可以零题。题量根据真实开发样例继续校准，但变更须版本化记录。

| 输入或问题 | 可供选择的用途或答案示例 | 对内容的影响 |
| --- | --- | --- |
| 高中生物：为什么学 | 高考备考、跟进课程、补基础、兴趣拓展 | 内容范围、题目风格与拓展边界 |
| 后端：为什么学 | 准备校招、工作中补基础、完成项目、兴趣探索 | 分支权重、讲解与练习情境 |
| 目前能做到什么 | 刚入门、了解概念、完成过简单任务、已有实践经验 | 前置知识与讲解起点 |
| 希望达到什么结果 | 建立整体认识、解释核心原理、解决实际问题、深入机制 | 内容粒度与停止位置 |

上述例子不构成领域白名单或用途推断规则。模型不能因为用户说“高中生物”就直接认定其备考，也不能默认所有后端学习都用于校招。

- 问题支持单选、多选、自由补充和“暂不确定”；允许以明确显示的默认假设开始。
- 多个用途可以指定主要目标与次要目标。只有答案会改变范围时，才追问教材、考试地区、学习阶段、时间约束等信息。
- 原始答案与整理后的设定都保留，明确区分用户陈述和模型假设。设定卡可直接修改，不额外要求逐项确认。
- 若未核对适用的考试或课程依据，不声称大纲符合官方范围，不把生成题标为官方真题。

学习设定至少表达主题、用途、已有基础、目标能力、纳入范围、暂不涉及的内容和已知约束。三个“度”分别理解为：

| 维度 | 含义 |
| --- | --- |
| 广度 | 当前目标涉及哪些主题、必要前置知识与相关联系 |
| 深度 | 对各主题需要能够解释什么、完成什么任务、理解哪些边界 |
| 难度 | 对当前用户而言，前置缺口、抽象程度和推理步骤带来的学习困难 |

树的层数不等于知识深度，节点数量不等于覆盖程度。LLM 根据设定作语义判断，程序不预先写死所有学科的难度或层级体系。

用户想达到的程度与其当前能力分别记录。自述与练习表现是不同证据，未知允许保留为未知；基础不足优先建议补前置知识，不悄悄降低用户目标。更改目标生成新的设定版本，已有内容保留，受影响的展开判断逐步重新评估。

## 节点内容与叶子规则

每个节点的概述应说明这里讲什么、与学习目标有什么关系、如何承接父层。详细讲解按需包含定义、动机、例子、适用范围、局限和进一步的问题，不强制套同一个完整模板。

分支应有清楚的职责和划分依据，避免无解释地混用“组成”“历史阶段”“应用场景”等维度。同一概念可以在不同路径出现，各路径的讲解重点与展开方式可以不同。教学分组也可以成为节点，不强迫所有节点对应独立概念。

LLM 明确输出节点可展开或为叶子，并提供简短理由。判断参照当前学习设定：所需内容是否已有承载位置、是否存在已知必要缺口、下一层是否增加有用且不重复的内容。

- 叶子表示当前目标下无需继续拆分，不表示知识已被穷尽，也不表示用户已掌握。
- 叶子在界面和服务端都禁止普通展开；补充解释、例子、练习和相关节点跳转仍可用。
- 可通过“终点不合适”反馈或修改学习目标触发重新评估，正式判定改变前不绕过限制。
- 补充当前节点解释与生成子节点是独立操作。看不懂某句话不应自动导致继续拆分。
- 生成失败、字段缺失、预算用尽或模型无法可靠说明，均不能被当作叶子判定。
- 程序的层数、数量、时间或费用限制属于执行限制，触发时显示暂停或限制原因，不显示“知识已讲完”。

界面分别表达展开判定、生成进度、内容覆盖/缺口和练习表现。普通浏览、阅读时长、展开次数以及少量答对都不直接代表掌握，不展示没有依据的“全领域完成百分比”。

初始大纲是可修订的组织方案。用户目标与模型划分分别保留；发现不适合现有分类的内容时，应记录缺口或重组建议，不能为维持旧大纲而忽略它。

## 练习与学习反馈

每个有知识内容的节点提供练习入口。练习可按需生成并保存，不要求浏览每个节点时自动生成大量题目，也不把答题作为继续阅读的门槛。

- 概览节点考查概念位置和关系；具体节点考查理解、辨析与应用；多个已学节点可以组成综合练习。
- 题目与当前已经提供的讲解、已知前置知识对齐，不默认要求尚未展开的细节。
- 首先支持单选、多选；每道题有考查点、选项、答案、解析和关联内容版本。错误选项尽量对应常见误解。
- 默认按需生成 3 题，单次允许 1～5 题。单选按稳定选项 ID 判分，多选按答案集合完全一致判分，暂不提供部分得分。
- 支持情境应用、结果预测、错误诊断和条件判断，避免只把正文原句挖空。
- 程序按已保存答案判分，作答后展示解析；题目答案本身仍可能出错，需要提供问题反馈和停用机制。
- 错题用于建议补充讲解、例子、前置知识或同考点的新题，不自动改动用户目标，也不自动把叶子变成可展开节点。
- 保留太简单、太难、需要例子、不符合用途等直接反馈，不把单次作答等同于稳定能力判断。

编程相关练习先支持读代码、找错误、选择实现、判断边界和方案取舍等选择题。运行示例与自动判题是两种能力；没有测试执行就不显示“代码验证通过”，选择题答对也不等于能够独立编程。

练习设计参考：[CMU 学习目标与评估一致性](https://www.cmu.edu/teaching/assessment/basics/alignment.html)、[CMU 概念测验](https://www.cmu.edu/teaching/assessment/assesslearning/concepTests.html)。这些资料支持设计原则，不代表本产品已经验证学习效果。

## 正文与非文本资源

采用 Markdown 正文、LaTeX 公式和结构化资源块组合的内容形态。模型根据教学目的选择系统支持的资源类型，不要求每个节点都有图片或动画。

| 类型 | 学习用途与交互 |
| --- | --- |
| Markdown 与公式 | 段落、列表、表格、引用、数学公式和静态代码 |
| 图示 | 流程、时序、结构与概念关系，配说明和文字替代 |
| 图片 | 真实照片、插图或示意图，配说明、来源或生成标记 |
| 可运行示例 | 查看/修改代码、运行、观察输出、恢复原始示例 |
| 交互演示 | 动画、参数实验、分步过程；根据需要提供播放、暂停、单步、重置 |
| 练习 | 与内容关联的原生答题界面 |

图片来源根据用途决定：真实照片、显微图像和历史实物优先检索有来源的资料；流程、几何和结构图优先由明确描述绘制；图表基于数据或公式；情境插画可以使用图像生成。科学示意图的结构与标注需要检查，生成画面不充当真实观察证据。外部资源保存来源与许可信息，实际检索或生成成功后才展示，不能使用模型编造的地址。

知识动画优先支持可操作的网页演示，例如排序单步执行、函数参数变化、通信时间轴和生物过程分阶段展示。已有演示组件由模型提供数据和参数；特殊需求可生成独立的小型网页资源，经过检查后嵌入。

首版运行示例和动画先支持受控的 HTML/CSS/JavaScript 环境。Python 浏览器运行可随后引入，需要完整后端、数据库或操作系统的环境另行设计。完整 LaTeX 文档导出和视频生成也属于后续能力。

正文可以先提交展示，非文本资源单独生成或加载。待生成、生成中、可用、失败需要可区分；失败时保留文字说明并允许重试。资源与知识版本关联，再次访问复用保存结果，不重新生成。

## 第一版边界提案

| 纳入第一版 | 留待需求或证据推动 |
| --- | --- |
| 用途问答、版本化学习设定、根节点与第一层大纲 | 特定学科的人工课程与领域专用引擎 |
| 节点概述、按需讲解和单层展开、叶子限制与反馈 | 全自动无限递归生成全部内容 |
| 保存、回退、重生成、失败重试、取消及基础一致性 | 多人共同编辑、社区发布、商业计费 |
| 基础概念引用、关系和前置提示、纠错与缺口记录 | 自动语义合并、复杂跨分支重组、跨知识空间共享 |
| 单选/多选练习、解析和答题记录 | 完整考试、间隔复习、自动掌握度模型、通用编程判题 |
| Markdown、公式、基础图示、图片、一个网页演示运行环境 | Python 运行、完整服务端沙箱、复杂模拟与视频生成 |
| 一个有明确来源的图片获取通道及资源持久化 | 根据预算和效果引入图像生成、更多图源 |
| 标记生成内容、范围、来源和不确定性 | 联网事实核验与课程标准对齐的完整流程 |

图片检索可以先于通用事实核验引入；取到一张真实图片不等于正文已经核验。资料上传不成为入口或必要条件。模型内容不能仅因通过结构校验或另一模型检查就被标为已证实，不应生成假引用。

初始大纲允许演化。新增子节点可按明确规则自动提交；替换已有结构、合并、删除和跨分支移动先提出预览，首版不自动执行破坏性重组。旧版本与用户手工修正需要得到保留。浏览复用已有结果，主动结构重生成使用新请求和修订；仍有效的叶子不能通过重生成绕过限制。

## 体验验收提案

- 用户不提供文件，从领域名经过简短问答即可得到学习设定、大纲与各节点概述。
- 同一领域选择不同用途、基础和目标时，大纲、解释程度、停止位置与练习应产生有意义的差异，不能只改措辞。
- 有充分细分价值的样例能连续深入至少三层；范围已足够小的样例应停止，不能为了层数硬拆。
- 在多个性质不同的领域验证，例如后端、音乐理论、摄影与历史；测试领域不成为产品白名单。
- 用户深入后仍能理解所在位置、当前解释范围与返回路径。
- 用户重新进入已有节点，不因普通浏览重复生成或出现不同的正式内容。
- 叶子在前后端都禁止普通展开，补充讲解与练习仍可用；目标变化或反馈需要正式重新评估。
- 题目有明确答案与解析，考查点与已提供内容对应；记录歧义、多解、错误答案和超出已讲范围的问题。
- 图片可追溯；公式与图示可渲染；动画可操作；代码示例是否执行、是否通过测试分别表达。
- 资源失败不阻塞已保存正文，资源更新不会无提示替换已有内容的版本。
- 错误、重试、取消与重组过程清楚可见，不让临时结果伪装成已保存内容。
- 记录重复概念、错误关系、明显遗漏与事实问题的人工检查结果；尚无验证数据。
