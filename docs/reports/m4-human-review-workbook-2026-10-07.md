## 一、报文骨架（限定 HTTP/1.1）

以下结构只适用于 HTTP/1.1 的文本报文；HTTP/2、HTTP/3 使用二进制帧，不适用本节的文本格式与边界规则。

- 请求：`请求行`（方法 + 目标 + 版本）→ 头部字段 → 空行 → 可选消息体。
- 响应：`状态行`（版本 + 状态码 + 原因短语）→ 头部字段 → 空行 → 可选消息体。

空行（CRLF）是头部与消息体的分界，没有它就无法确定头部何时结束。

## 二、消息体边界：请求与响应规则不同

**请求**：若既无 `Content-Length` 也无 `Transfer-Encoding`，则消息体长度为零，服务端不应再读取字节。

**响应**：先判断是否允许有消息体——1xx、204、304 以及 HEAD 的响应无消息体；CONNECT 的 2xx 响应后连接转为隧道，不按普通消息体处理。只有允许有体时，才依次考虑：`Transfer-Encoding`（分块传输）→ `Content-Length` → 以上都没有则由关闭连接定界。

因此「无长度即无体」只对请求成立，对响应必须结合状态码与方法判断。

## 三、头部字段合并与 Set-Cookie 例外

同名字段可合并为一行，但必须符合列表语法：`A: 1, 2` 等价于两行 `A: 1` 与 `A: 2`。

`Set-Cookie` 是例外：它不适用逗号合并，因为 Cookie 值本身可能含逗号（如 `Expires=Wed, 21 Oct 2025 07:28:00 GMT`），合并会破坏语义。多个 `Set-Cookie` 必须各占一行。

## 四、一个完整 JSON 报文示例（HTTP/1.1）

请求（无长度与传输编码，故消息体为零）：

```http
POST /api/login HTTP/1.1
Host: example.com
Content-Type: application/json

```

响应（200，正文为展示内容）：

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 25

{"token":"abc","ok":true}
```

正文 `{"token":"abc","ok":true}` 的 UTF-8 字节数为 25，与 `Content-Length` 一致。该长度只计算展示正文，不含 Markdown 围栏的收尾换行；若无法确定字节数，应省略具体数字，交由 HTTP 库计算。

## 五、常见误判

- 把请求的「无长度即无体」套到响应上，导致把关闭连接定界的响应误判为无体。
- 忽略 204/304/HEAD 的无体规则，按 `Content-Length` 去读不存在的体。
- 把多个 `Set-Cookie` 合并成一行，导致 Cookie 解析错乱。
- 把 HTTP/1.1 文本报文格式推广到 HTTP/2 或 HTTP/3。

## 这一步在做什么

当前查找区间是整个数组，左边界 $l = 0$，右边界 $r = 2$（下标从 0 开始）。

- 定区间：$[l, r] = [0, 2]$
- 取中点：$m = l + (r - l) // 2 = 0 + (2 - 0) // 2 = 1$
- 取值：$a[1] = 3$
- 比较：$a[1] = 3$ 与目标值 $3$ 相等

比较结果是**相等**，所以这一步就判定「找到了」，不需要再看下标 0 或 2 的元素。

> 注意：这里只描述一次比较的结果，不涉及循环、边界更新或完整二分查找流程。

## 中点公式与适用前提

这里使用非负数组下标：$0\le l\le r\le M$，其中 $M$ 是整数类型的最大值。因此 $0\le r-l\le r$，并且 $l\le l+\lfloor(r-l)/2\rfloor\le r$，差值和最终中点都不会超出可表示范围。只写 $l\le r$ 并不足以保证这个结论。

直接计算 `(l + r) / 2` 可能先让数学和超出整数类型上限；改写为 `l + (r - l) / 2` 在上述非负下标前提下避免这个中间求和问题。

### 不同语言分别处理

- Java 的 `int` 是 32 位有符号整数，整数加法溢出保留数学和的低 32 位，可能回绕为负数。例如两个 `2000000000` 相加，结果按 Java 的整数规则回绕；这只是运算示例，不创建大数组。
- 标准 C 的有符号整数溢出属于未定义行为，不能承诺它固定回绕或一定得到负数。C 的 `int` 位宽由实现决定，也不能普遍假定为 32 位。
- Python 内建 `int` 是任意精度整数。在这里的整数算术中，`(l + r) // 2` 与 `l + (r - l) // 2` 结果相同；不需要后一写法来避免 Python 整数溢出。

```python
a = [1, 3, 5]
target = 3
l, r = 0, 2
m = l + (r - l) // 2
value = a[m]
print(m, value, value == target)  # 1 3 True
```

此代码只说明一次中点比较，没有展开循环和边界更新。

流程：定区间 l=0, r=2 → 取中点 m=1 → 取值 a[1]=3 → 与目标值 3 比较 → 相等，确认找到目标。小于或大于的分支属于完整二分查找流程，本节点不展开。

## 小结

- 本节点情境下，一次中点比较的结果是**相等**，目标值 3 已找到。
- 中点公式 $l + (r - l) // 2$ 相比 $(l + r) // 2$，在定长整数语言中避免了 $l + r$ 的溢出。
- Python 的整数不会溢出，两种写法结果相同；采用前者主要是为了跨语言一致与语义清晰。
